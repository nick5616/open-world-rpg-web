G5 4 vCPU follow-up: in-process scenario 1 benchmark (300 players + 2,000 awake enemies, the whole zone tick, no sockets),
official world terrain (LODESTONE_BENCH_TERRAIN=1), GOMAXPROCS=4, -test.cpu 4, 900 ticks after a 150-tick warm-up.
2026-11-09 ~18:10 UTC, Windows 11 desktop, i7-11700K (8 cores / 16 threads; GetLogicalProcessorInformation: core k =
logical CPUs 2k and 2k+1), quiet at the time (whole-machine load 1-7 % before/during each run).

  mask=F000 = logical CPUs 12-15 = cores 6-7 with their SMT siblings: a 4 vCPU slice, the failing G5 case
  mask=5500 = logical CPUs 8,10,12,14 = 4 physical cores, one thread each (the Linux "cores4" case)

  start /affinity <mask> /wait /b game.test.exe -test.run NONE_ -test.bench Scale/p300_e2000 -test.cpu 4 -test.benchtime 900x

basem = main @ ee7902a with only the benchmark's new metrics; v7 = branch g5-tick-vcpu4 (same code as the final commit for
everything the benchmark runs; the GC default in server/zone/gc.go is the zone binary's, not the test's). Base and after
alternate inside each repetition. Windows caveats: Go's clock steps ~0.5 ms there, so p50/p99/max are quantized to ~0.5 ms;
cpu-Mcycles is QueryProcessCycleTime per tick over all threads (the total work; Windows process times are sampled too
coarsely to use).
